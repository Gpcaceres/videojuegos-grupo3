\section{Especificación de Requerimientos (IEEE 830)}
% =====================================================================

\subsection{Introducción}

\subsubsection{Propósito}
Este documento especifica los requerimientos del videojuego educativo
\emph{Tres en Raya con IA} en su versión web. Va dirigido al docente de la
asignatura y a los integrantes del grupo.

\subsubsection{Alcance}
El sistema permite que un usuario juegue al Tres en Raya contra un
\emph{Jugador Controlado por la Computadora} (JCC) desde un navegador. La
JCC decide sus jugadas con el método numérico heurístico de la referencia
(pesos usuario = 1, JCC = 3, vacío = 0). El nivel implementado es
\textbf{UnbeatableAI}; la arquitectura deja preparados los niveles
\textbf{MediumAI}, \textbf{UnbeatableAI $\rightarrow$ MinMax},
\textbf{Principiante} y \textbf{Dos jugadores}.

\subsubsection{Definiciones, acrónimos y abreviaturas}
\begin{description}[leftmargin=2.6cm,style=nextline]
  \item[JCC] Jugador Controlado por la Computadora (marca ``0'').
  \item[Usuario] Jugador humano (marca ``X''); siempre empieza.
  \item[mArrayMoves] Vector $V_k$ de 9 posiciones con los pesos 0/1/3.
  \item[API REST] Interfaz HTTP/JSON entre el frontend y el backend.
  \item[SPA] \emph{Single Page Application}, aplicación web de una sola página.
\end{description}

\subsubsection{Referencias}
\begin{itemize}
  \item IEEE Std 830-1998, \emph{Recommended Practice for Software Requirements Specifications}.
  \item Villacís, C. et al., \emph{Optimización del Juego del Tres en Raya con
        Niveles de Dificultad, Utilizando Técnicas Heurísticas de IA}, ESPE.
  \item Material de clase: \emph{Caso 1}, \emph{Caso 2} y \emph{Caso 3 TTT}.
\end{itemize}

\subsection{Descripción general}

\subsubsection{Perspectiva del producto}
Es una aplicación cliente--servidor. El \textbf{backend en Go} contiene
\emph{toda} la lógica del juego (port 1:1 de las clases C\#) y la expone como
API REST. El \textbf{frontend en Angular} solo dibuja el tablero, envía los
clics y anima los eventos que devuelve el servidor.

\subsubsection{Funciones del producto}
Seleccionar modo de juego, iniciar una partida nueva, marcar una casilla,
recibir la jugada de la JCC, conocer el resultado (``Ganó X'', ``Ganó 0'' o
``Empate''), ver el marcador y ver cómo razona la IA (pesos y sumas por línea).

\subsubsection{Características de los usuarios}
Niños de 7 a 11 años (público objetivo del juego original) y estudiantes.
No se requiere conocimiento técnico: basta con hacer clic o usar las teclas
1--9.

\subsubsection{Restricciones}
\begin{itemize}
  \item La lógica del juego no puede modificarse respecto al original.
  \item Backend en Go~1.23 o superior, solo con la librería estándar.
  \item Frontend en Angular~22 con navegadores modernos (Chrome, Edge, Firefox).
\end{itemize}

\subsubsection{Suposiciones y dependencias}
El servidor Go está disponible en el puerto 8080; en desarrollo, Angular
redirige \texttt{/api} mediante \texttt{proxy.conf.json}.

\section{Modelo de Inteligencia Artificial}
% =====================================================================
El tablero se representa como el vector $V_k$, con $k = 0,\dots,8$, en el
arreglo \texttt{mArrayMoves}. Cada casilla vale 0 (vacía), 1 (usuario) o
3 (JCC). Para cada una de las 8 líneas se calcula la suma de sus tres
casillas:

\begin{table}[H]
\centering
\caption{Interpretación de la suma por línea}
\begin{tabular}{cll}
\toprule
\textbf{Suma} & \textbf{Composición} & \textbf{Acción de la JCC}\\
\midrule
6 & 3 + 3 + 0 & Completar la línea y \textbf{ganar} (Caso 2)\\
2 & 1 + 1 + 0 & \textbf{Bloquear} al usuario (Caso 1)\\
5 (diagonal) & 1 + 3 + 1 & Caso trivial: esquina libre o lado aleatorio (Caso 3)\\
\bottomrule
\end{tabular}
\end{table}

La regla de bloqueo en Go conserva el mismo orden de evaluación que el C\#:

\begin{lstlisting}[language=Go]
// pick devuelve el primer casillero vacío de la línea (a, b, d).
func (c *ControlStrongIntelligentMoves) pick(a, b, d int) int {
	index := 0
	if c.ArrayMoves[a] == 0 { index = a
	} else if c.ArrayMoves[b] == 0 { index = b
	} else if c.ArrayMoves[d] == 0 { index = d }
	c.sum = c.ArrayMoves[a] + c.ArrayMoves[b] + c.ArrayMoves[d]
	return index
}
\end{lstlisting}

\subsection{Diseño}
La arquitectura separa responsabilidades en dos capas:
\begin{itemize}
  \item \textbf{Backend (Go):} \texttt{internal/game} contiene la lógica
        (sin dependencias web) e \texttt{internal/api} expone las rutas.
        \texttt{Board} reemplaza a los controles de Windows Forms
        (\texttt{ListButtons}, \texttt{GroupBox} y \texttt{MessageBox}), de modo
        que el código de los controladores queda casi línea por línea igual al
        original.
  \item \textbf{Frontend (Angular):} componentes \emph{standalone} con
        \emph{signals}, sin \texttt{zone.js}. \texttt{GameStore} reproduce los
        eventos del backend con pausas para animarlos y no decide ninguna jugada.
\end{itemize}

\subsection{Hallazgo sobre la lógica original}
La prueba exhaustiva muestra que la JCC del método numérico \textbf{pierde en
cerca del 1,2\,\% de los caminos posibles}. Esto no es un error del port: la
lógica original cae en \texttt{GenerateRandomNPCMove} cuando ninguna regla
aplica, y a veces deja al usuario un \emph{tenedor} (dos amenazas a la vez).
Ejemplo: X en 0, JCC en 4, X en 7, JCC en 2 (al azar), X en 6. La JCC solo
puede tapar una de las amenazas (0--3--6 y 6--7--8), y el usuario gana.

Como la especificación exige conservar la lógica, el comportamiento se
mantiene y se documenta. Es justamente la motivación de la variante
\textbf{UnbeatableAI $\rightarrow$ MinMax}, que explora el árbol completo de
jugadas y no puede caer en un tenedor.

\section{Conclusiones y Recomendaciones}
% =====================================================================
\subsection{Conclusiones}
\begin{itemize}
  \item Se migró la IA UnbeatableAI de C\# a Go sin alterar su lógica. Las
        pruebas reproducen los Casos 1, 2 y 3 del material de clase.
  \item Separar la lógica (backend) de la presentación (frontend) permitió
        sustituir Windows Forms por una interfaz web animada sin tocar el
        algoritmo.
  \item El método numérico basado en pesos 1/3/0 es simple y eficiente, pero
        no es estrictamente imbatible: su caída al azar deja un 1,2\,\% de
        caminos perdedores.
\end{itemize}

\subsection{Recomendaciones}
\begin{itemize}
  \item Implementar la variante MinMax para garantizar una IA realmente imbatible.
  \item Agregar las reglas de ``bloquear tenedor'' si en el futuro se permite
        modificar la heurística.
  \item Desplegar el backend en un servicio en la nube (por ejemplo Cloud Run)
        y el frontend como sitio estático.
\end{itemize}
